# 路线图

已经商定、按顺序一项一项做的方向。每一项开始前先给出详细计划，批准后再动手。

## 已完成

- **0.14.0 拆开引擎、轻写法、文件夹节点。** 引擎内部按职责拆成几个部件；普通函数直接当节点，`@node`、协议可省、`run()` 一步运行；整个文件夹作为一个节点。

- **运行中按显式操作改图。** `ctx.change(Change())`：检查、立刻生效、写进日志、恢复时重做。

- **跨进程、跨机器的节点。** `serve_node` / `interlacing node-serve` 把节点放在它所在的地方常驻服务，图里用 `RemoteNode` 代表；TCP 上一行一个 JSON，带停止信号和用量；不在本机监听要令牌，图文件只能连允许的地址。流和调用仍然只在进程内。

- **协程节点。** `async def run` 的节点在引擎的事件循环上被 await，不各占一个线程，超时被取消；`await ctx.acall`。多线程时每个信封六七十微秒的开销来自 Python 线程交接，协程不会让同步节点变快，所以同步节点仍在线程里。模型接口目前还是同步的，以后需要时可以用标准库写异步 HTTP。

- **每个节点的开关。** 暂停、恢复、停止、重启，单个或成批；图里写明谁管谁，上级只能拨下面的节点；写进日志、恢复时保持。开关也管到进程外：别的进程里跑着的运行通过运行目录拨，`RemoteNode` 的远端停在它的下一步，外部程序跟着挂起（Linux、macOS），程序自己的时限也停表。这是“以 agent 为中心”计划的第 1 阶段。

- **常驻 agent 和任务栏。** 任何节点都能在激活中途收消息（`ctx.receive`，等的时候不占工作名额，互相等不会卡死）和存档进度（`ctx.commit`，中断后接着做）。在这之上，`AgentNode(resident=True)` 一直在，直到自己 `finish`：先发做好的部分、`wait` 等别人、任务栏（`plan`、`done`、`note`）。普通函数可以直接当 agent 的工具，自带 `time_left`。这是第 2 阶段。

## 未来计划

以 agent 为中心的计划（[设计与分阶段计划](https://claude.ai/artifact/9NoHnubxG88ZNrSTFkqLbP)）接下来按顺序做第 3、4 阶段（详细计划：[第 2–4 阶段详细计划](https://claude.ai/artifact/7eZRKDhu5TMv1D116CGA6p)）。每个阶段开始前先在聊天里讲清楚做法，同意后再动手。

### 3. 更正

agent 发现自己之前发出的消息错了，可以发一条更正（`replaces`）。

- 对方还没读的旧消息，直接在信箱里换掉。
- 程序节点收到更正就自动重跑，并把更正继续往下游传。
- agent 收到更正会被告知，自己决定怎么处理。
- 每个节点都可以用 `on_correction`（rerun / tell / ignore）自己定。

### 4. 管辖和招人

自由的 agent 在自己的目录和子图里有完全的权利，层层管理：主控管子控，子控管次子控。

- agent 可用的工具：`hire`（按目录里的模板招下属）、`connect`、`dismiss`、`control`。
- 嵌套工作区：每个下属有自己的目录。
- 开关和上下级跨过子图：节点内部再跑的一张图里的节点，也能被它的上级和操作者拨到。这是检查报告里留下的一项。
- 运行中新加的节点可以指定上级。这也是检查报告里留下的一项。

### 以后再看

这些不在上面的阶段里，等需要时再做：

- 看得见的运行：`interlacing show` 把图画出来（Mermaid 或 DOT），再按日志列出时间线，包括谁在第几轮、用了多久、花了多少、哪里出错、开关什么时候被谁拨过。
- 流和调用跨进程（`Transport`）。现在节点可以在别处，但节点之间的边只在进程内。
- 模型接口改成异步 HTTP（标准库）。现在模型调用是同步的，在线程里跑。
- 暂停中的等待改成纯事件唤醒，不再轮询（现在线程每 0.1 秒、协程每 0.05 秒看一次）。
- Windows 上暂停外部程序本身。现在只有节点在等，程序继续跑。
- 在真实模型服务上做更完整的测试，包括思考和图片输入；MCP 服务接一次桌面应用。
